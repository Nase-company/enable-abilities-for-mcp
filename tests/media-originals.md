# Preserved-original test evidence

Run `php tests/media-original-test.php` for isolated native filesystem/parser/input checks.
Run `python tests/run-media-originals.py --evidence "$TMPDIR/ewpa-originals-run"` for the real WordPress spike and acceptance. Requires pre-existing Docker images `mariadb:11` and `wordpress:php8.3-apache`; it never pulls images. Keep receipts outside the repository. Randomly named owned containers have 256/384 MiB memory limits; their anonymous volumes are removed and absence is checked. No existing container, global prune, production URL or client data is used.

The spike creates a genuine native JPEG attachment, lowers WordPress's big-image threshold for tiny synthetic files, and proves same-path atomic replacement leaves complete raw post/meta rows, original/main URLs and every generated variant byte unchanged. The shipped feature was first exercised RED (missing inspect callback), then GREEN.

The acceptance covers fresh activation/default-off policy, administrator/native permissions (including denial of an author on their own attachment), success in JPEG/WebP, all attachment post/meta rows and variant bytes, preserved mode/ownership and refreshed HTTP modification time, source-dimension consistency, protection of another attachment's recorded file, stale input and actual source/DB drift, source drift during copy/recheck, no-benefit/replay, independent DB-connection lock contention, missing/unsafe/traversal/equal paths, symlinks/hardlinks/linked parent, unsupported bytes and disabled filesystem functions. Real HTTP uses native application-password authentication against the core Abilities REST route, not a synthetic endpoint or direct-call-only substitute. It verifies disabled write 404, subscriber denial, inspect, replacement, stale replay and independent CLI readback. Credentials are randomly generated in disposable fixtures, retained only in process memory or temporary mode-0600 Docker environment files; no secrets appear in receipts or command arguments.

Success requires `SPIKE_VALIDATED`, `MEDIA_ORIGINAL_ACCEPTANCE_OK`, `HTTP_ABILITIES_ACCEPTANCE_OK` and `MEDIA_ORIGINAL_DOCKER_OK`, not merely exit zero (WordPress error HTML can exit zero). Fixture assertion exceptions fail the process. Receipts distinguish mock-free WordPress integration from the smaller unit doubles.

PHP `fsync` is required for this conservative operation (PHP 8.1+); the plugin's inherited general PHP minimum remains 8.0 and the feature fails closed there. Tested with image-provided PHP 8.3 and WordPress 7.1.4, not every supported WordPress/PHP/filesystem combination. Real cloud archival, crash/power-loss recovery, ACL/xattr retention and simultaneous noncooperating optimizer/editor writes are not claimed.

For a fork ZIP, run `composer install --no-dev`, then `php build-release-zip.php 2.14.1 --local` on PHP with ZipArchive. Run the same native suite against the actual archive with `python tests/run-media-originals.py --package dist/enable-abilities-for-mcp-2.14.1.zip --evidence "$TMPDIR/ewpa-package-run"`; fixtures are mounted separately and must not exist in the package. The old default build intentionally still exports an upstream SVN tag; use `--local` for NC releases. The local mode requires no-dev dependency metadata, copies only allowlisted production roots, rejects symlinks and preserves the existing package denylist (including all tests/fixtures). A fork Update URI prevents upstream auto-overwrite, but is not an automatic GitHub updater.
